## งานแทรก — ปลดระวางแอป `/donate`

ตรวจโค้ด PHP เดิมแล้วพบสองเรื่องที่ต้องจัดการทันที:

1. **`login.json` เปิดอ่านได้จากอินเทอร์เน็ต** — `GET /donate/login.json` คืน 200
   พร้อมรหัสผ่านแอดมินเป็น plaintext · `donate_list.json` ก็เปิดอ่านได้ (ข้อมูลผู้บริจาครั่ว)
2. **แอปเขียนไฟล์ไม่ได้มาตั้งแต่แรก** — lsphp รันเป็น `ppzst1542` แต่ไฟล์เป็น `janitor:janitor 644`
   `file_put_contents()` คืน false เงียบ ๆ (โค้ดไม่ได้เช็ก) = ระบบพังอยู่ก่อนแล้ว

ปัญหาอื่นในโค้ด: ไม่มี auth ฝั่งเซิร์ฟเวอร์เลย (`action=approve` ยิงตรงได้),
stored XSS ผ่าน `innerHTML`, `Access-Control-Allow-Origin: *`, ไม่มี rate limit,
read→write ไม่มี lock, `confirm` จับคู่ด้วย name+message+amount แทน id

**ทำ:** สำรองทั้งโฟลเดอร์ → ย้ายโค้ดและข้อมูลออกนอก webroot (`donate-legacy/` chmod 700)
→ เหลือหน้าแจ้งปิดปรับปรุง + `.htaccess` ที่ 403 ไฟล์ `.json`/`.php`

**ตรวจผล:** `login.json`, `donate_list.json`, `api.php` → 403 · path อื่นวิ่งเข้าหน้าแจ้งปิด

**เก็บไว้ใช้ต่อ:** `generatePromptPayPayload()` ในโค้ดเดิมเขียนถูกต้อง (EMVCo + CRC16-CCITT)
ยกมาแปลงเป็น TypeScript ในเฟส 4

## เฟส 1 — โครงระบบ + ฐานข้อมูล

**สร้าง**
- โปรเจกต์ Next.js 16.3.2 + React 19.2.8 + Tailwind 4 + TypeScript ที่ `/home/ppzstudio.com/ppzweb`
- ฐานข้อมูล `ppz_web` (utf8mb4_unicode_ci) + Prisma schema 16 ตาราง + migration + seed
- `src/lib/db.ts` (Prisma + driver adapter), `src/lib/redis.ts`, `/api/health`
- pm2 `ppzweb` cluster 2 instances, `deploy.sh`, ฟอนต์ไทย (Anuphan + IBM Plex Sans Thai)
- vhost `dev.ppzstudio.com` + SSL Let's Encrypt + บังคับ HTTPS + `X-Robots-Tag: noindex`

**เรื่องที่ต่างจากแผน**
- ใช้ **Next.js 16 ไม่ใช่ 15** เพราะ kruthai.app บนเครื่องนี้รัน 16 อยู่แล้วและ Node 20.20 รองรับ
- **Prisma 7** ย้าย connection URL ออกจาก schema ไป `prisma.config.ts` และต้องต่อผ่าน driver adapter
- `prisma migrate dev` ต้องใช้ shadow database — ผู้ใช้ `ppz_web` ไม่มีสิทธิ์ `CREATE DATABASE`
  (error P3014) จึงสร้าง `ppz_web_shadow` ไว้ให้ล่วงหน้า

**สะดุด:** CyberPanel สร้าง vhost มาแล้ว docRoot พาธซ้ำซ้อน (`/home/ppzstudio.com//home/…`)
ทำให้ vhost ไม่ทำงานเลย (ทุก path ตอบ 404) · และ SSL ผ่าน ZeroSSL ล้มเหลว
(`Replay-Nonce header not found`) มันเลย fallback ไปใส่ใบ self-signed
→ เขียน vhost.conf ทับใหม่ + ออกใบจริงด้วย certbot

  · autosave ทุก 10 วินาที · เตือนตอนปิดแท็บทั้งที่ยังไม่บันทึก
- อัปโหลดรูป: sharp แปลง WebP 3 ขนาด + blur placeholder · ตั้งชื่อไฟล์ใหม่ · ตรวจชนิดจากเนื้อไฟล์จริง
- ตัวแปลง slug ไทย→อังกฤษ (`"วิธีตั้งค่า OBS ให้ไลฟ์ลื่น"` → `withitangkha-obs-studio-hailailuen`)
- sanitize HTML ฝั่งเซิร์ฟเวอร์ · เก็บ revision 20 เวอร์ชันล่าสุด

**บั๊กที่เจอ**
1. **OpenLiteSpeed ตีกลับ 400 ให้ POST/PATCH ที่ไม่มี body** ตั้งแต่ยังไม่ถึง Node
   ไม่มีร่องรอยใน log แอปเลย · ปุ่ม "เขียนบทความใหม่" ที่ยิง `fetch(url,{method:"POST"})` เปล่า ๆ พัง
   → ส่ง `body:"{}"` เสมอ (`DELETE` ไม่มี body ผ่านได้ปกติ)
2. `NEXTAUTH_URL` ที่ตั้งตายตัวทำให้ dev redirect ข้ามไป production → ลบทิ้ง ใช้ `AUTH_TRUST_HOST`
3. `extraHeaders Cache-Control` ทำให้ได้ header ซ้อนสองอัน → ต้องใช้ syntax `set`
4. `Btn` ถูกประกาศในตัว `Toolbar` ทำให้ React remount ปุ่มทั้งแถบทุก render (lint จับได้)

**ทดสอบ:** ยัด `<script>alert()</script>` และ `onclick=` ในเนื้อหา → ถูกตัดทิ้งทั้งคู่ ·
ลิงก์นอกได้ `rel="noopener noreferrer"` อัตโนมัติ · ล็อกอินผิด 5 ครั้งแล้วใส่รหัสถูก → ยังถูกบล็อก

## เฟส 2.5 — แก้ตามที่เจ้าของทดลองใช้

เจ้าของทดลองเขียนบทความจริงแล้วแจ้งกลับมา 4 ข้อ:

1. `บันทึกร่าง` → `บันทึก`
2. `ตั้งเวลาเผยแพร่` / `เผยแพร่` → `เผยแพร่` คำเดียวตลอด
3. `ถอนกลับเป็นร่าง` → `กลับเป็นฉบับร่าง`
4. **slug ไม่ตามหัวข้อ** — บั๊กจริง

ข้อ 4: ตอนกดสร้างร่าง ระบบตั้ง slug ชั่วคราวเป็น `draft-xxxxx` แล้วหน้าเว็บส่งค่านั้นกลับขึ้นไป
ทุกครั้งที่ autosave ไม่มีจุดไหนเอาหัวข้อมาคำนวณใหม่เลย (ตอนทดสอบผ่าน API ส่ง slug ไปเองเลยไม่เจอ)

**แก้:** slug กลายเป็นค่าที่คำนวณจากหัวข้อสด ๆ ตอน render · แตะแก้เองเมื่อไหร่จะหยุดตาม ·
บังคับบันทึกก่อนเผยแพร่เสมอ · ใส่กติกาเดียวกันฝั่งเซิร์ฟเวอร์เป็นตาข่ายรอง

> **ความผิดพลาดที่เกิดขึ้น:** ตอนเก็บกวาดข้อมูลทดสอบของตัวเอง ใช้ `DELETE FROM posts`
> แบบไม่ระบุเงื่อนไข ทำให้บทความทดสอบอันแรกของเจ้าของถูกลบไปด้วย
> ตั้งแต่นั้นเป็นต้นมาการลบทุกครั้งระบุเงื่อนไขเจาะจงเสมอ

## เฟส 4 — ผลงาน · ค้นหา · cron · โมดูลสนับสนุน

**จัดการผลงาน** — ตัวเขียนเหมือนบทความ + ฟิลด์เฉพาะผลงาน · แกลเลอรีอัปหลายรูป

· สร้างผลงานใหม่ได้โครง 3 ท่อนให้เลย (โจทย์ / สิ่งที่เราทำ / ผลลัพธ์)

**ค้นหา** `/search` — หาทั้งบทความและผลงาน

```
0 3 * * *    สำรอง DB + uploads เก็บ 14 วัน
```

**โมดูล `/support`** — สร้าง QR พร้อมเพย์ฝั่งเซิร์ฟเวอร์ · แนบสลิป · อนุมัติที่ `/admin/donations`
· เติมเศษสตางค์ให้ยอดไม่ซ้ำเพื่อจับคู่กับสลิป (พร้อมเพย์ไม่มีช่องแนบข้อความถึงผู้รับ)

PromptPay payload ที่แปลงมาเป็น TypeScript **ตรงกับ PHP เดิมทุกตัวอักษร** (เทียบแล้ว byte ต่อ byte)

**บั๊กที่เจอ**
1. **pm2 cluster ทำให้ "เผยแพร่แล้วไม่เห็นผล"** — Next เก็บ ISR cache ในหน่วยความจำของแต่ละ process
   ซึ่งไม่แชร์กัน `revalidatePath()` เลยล้างได้แค่ instance ที่รับคำขอ
   อาการคือรีเฟรชแล้วเนื้อหาสลับไปมาระหว่างเก่ากับใหม่
   → `cacheMaxMemorySize: 0` ให้ทั้งสองอ่านจาก `.next/cache` บนดิสก์ที่เป็นที่เดียวกัน
2. **แผนเดิมเขียนผิดเรื่องค้นหาไทย** — บอกว่าจะใช้ `FULLTEXT WITH PARSER ngram`
   แต่ **MariaDB ไม่มี ngram parser** (มีแต่ใน MySQL) และ FULLTEXT ปกติหาไทยไม่เจอเลย
   ทดสอบได้ 0 แถว เทียบกับ LIKE ที่ได้ถูก → เปลี่ยนไปใช้ LIKE
3. `confirmDonation` คืนค่าคนละรูปแบบสองทาง (build จับได้)
4. sitemap ไม่อัปเดตตอนเผยแพร่ → เพิ่ม revalidate ให้ sitemap + RSS

**เก็บงาน:** `/donate` → 308 `/support` · security headers ครบ · ซ่อน `x-powered-by`

**แจ้ง Bing ผ่าน IndexNow** ตอบ 202 (key เก็บใน `.env`)

## หลังขึ้นเว็บ — กันงานหายและเก็บความปลอดภัย

ตรวจหลังส่งมอบแล้วพบว่า **งานทั้งหมดมีอยู่ที่เดียว** — โค้ดยังไม่ได้ commit เลยสักครั้ง
(มีแค่ commit ของ create-next-app) ไม่มี git remote · `backup.sh` สำรองแค่ DB กับรูป
ไม่รวมโค้ดและ `.env` · และไฟล์สำรองเองก็อยู่ `/dev/sda1` ดิสก์เดียวกับเว็บ
CyberPanel ก็ไม่ได้ตั้ง backup ออกนอกเครื่องไว้ (destination 0 แถว)

แปลว่าถ้าดิสก์พัง ทุกอย่างหายพร้อมกันหมดรวมทั้งไฟล์สำรอง

**ที่ทำ**

1. **สแกนความลับก่อน commit** — เจอรหัสผ่านจริงของ `/donate` เดิมอยู่ใน `docs/worklog.md`
   แก้เป็นคำอธิบายแทน (ถ้าหลุดเข้า git history แล้วเอาออกยากมาก)
2. **commit โค้ดทั้งหมด** 105 ไฟล์ / 13,244 บรรทัด — รวมเป็น commit เดียวเพราะเป็นการนำเข้า
   โค้ดที่ขึ้นเว็บไปแล้ว แยกย่อยตามเฟสจะได้ commit ที่ build ไม่ผ่านและ `git bisect` ใช้ไม่ได้
3. **push ขึ้น GitHub private** `paakpoomz/ppzstudio.com` ผ่าน **SSH ไม่ใช่ token**
4. **เพิ่ม `git bundle` + `.env` เข้ารหัส AES256 เข้าไปในชุด backup**
   passphrase อยู่ที่ `/root/.ppz-backup-key` และต้องมีสำเนาใน password manager ของเจ้าของ
5. **ทดสอบกู้คืนจริง** — clone bundle ได้ครบ 117 ไฟล์พร้อม history · ถอดรหัส `.env`
   ได้ตรงต้นฉบับทุกตัวอักษร · ใช้ passphrase ผิดแล้วเปิดไม่ได้ · เขียน `docs/restore.md`
6. **ทดสอบ `deploy.sh` ทั้งเส้น** — เดิมบรรทัดแรกคือ `git pull` ซึ่งจะพังทันทีเพราะไม่มี remote
   ตอนนี้รันผ่านครบทุกขั้น

**พบระหว่างทาง: GitHub token หลุด 4 ตัว**

| ที่ | ชนิด | จำนวน |
|---|---|---|
| `.git/config` ของ kruthai + freelanceTH | `ghp_…` | 1 (ใช้ร่วมกัน) |
| `/root/.bash_history` | `github_pat_…` | 2 |
| `/home/janitor/.bash_history` | `github_pat_…` | 1 |

`github_pat_` (fine-grained) เป็นคนละรูปแบบกับ `ghp_` — สแกนแค่แบบเดียวจะพลาด
และ token ไม่ได้อยู่แค่ใน config มันติดใน **shell history ของทุก user** ที่เคย
`git clone` ด้วย URL ที่มี token

ลบร่องรอยออกจากทุกไฟล์ (แทนที่เฉพาะตัว token เก็บคำสั่งไว้) · เปลี่ยน remote ของ
kruthai กับ freelanceTH เป็น SSH · เจ้าของ revoke token ทั้งหมดใน GitHub แล้ว
ทดสอบหลัง revoke: `git fetch` ผ่านทั้ง 4 repo เว็บและ pm2 ปกติ

## สถานะปัจจุบัน

**เสร็จแล้ว:** ระบบครบทุกฟีเจอร์ที่วางไว้ · ขึ้นเว็บจริงแล้ว · cron ทำงาน · สำรองอัตโนมัติทุกคืน

**ค้างอยู่ฝั่งเจ้าของเว็บ**
1. เขียนบทความจริง (ตอนนี้ `/blog` ยังว่าง)
2. เอาผลงานเก่าขึ้น (`/works` ยังว่าง)
3. ยืนยัน Google Search Console แล้วส่ง `https://ppzstudio.com/sitemap.xml`

**ที่ยังไม่ได้ทำ (ไม่ได้อยู่ในแผน แต่เคยคุยถึง)**
- หน้าจัดการแท็ก (ตอนนี้แท็กสร้างอัตโนมัติตอนพิมพ์ แต่แก้ชื่อ/ลบไม่ได้)
- หน้าตั้งค่าเว็บในหลังบ้าน (ตอนนี้แก้ตาราง `settings` ตรง ๆ)
- Turnstile ในฟอร์มติดต่อ (ต้องมี key จาก Cloudflare — ตอนนี้ใช้ honeypot + rate limit)
- role EDITOR ยังไม่ได้ใช้จริง (มีผู้ใช้คนเดียว)

**หมายเหตุค้าง:** รหัสผ่านแอดมินของ `/donate` เดิมที่เคยเปิดอ่านได้จากอินเทอร์เน็ต เจ้าของแจ้งว่ายังไม่ซีเรียส
ถ้าเปลี่ยนใจอยากไล่เปลี่ยนทุกที่ที่ใช้ซ้ำ (CyberPanel, FTP, DB, อีเมล, SSH) บอกได้
